# SPbU Schedule Bot

Telegram-бот, который присылает расписание пар (группа 25.М12-ия,
https://timetable.spbu.ru/FL/StudentGroupEvents/Primary/474739) по команде
и автоматически каждый вечер — расписание на завтра.

Расписание не скроллится через браузер: страница СПбГУ отдаёт готовый HTML,
поэтому бот просто скачивает его (`requests`) и разбирает (`BeautifulSoup`).
Никакого headless-браузера не нужно.

## Что внутри

- `bot.py` — сам бот: команды `/today`, `/tomorrow` и ежедневная рассылка
- `scraper.py` — загрузка и разбор HTML со страницы расписания
- `formatter.py` — сборка текста сообщения
- `config.py` — токен, время рассылки и **список сокращений/исключений
  предметов** — самое интересное для редактирования

## 1. Создать бота в Telegram

1. Открой [@BotFather](https://t.me/BotFather), отправь `/newbot`
2. Придумай имя и username (должен заканчиваться на `bot`)
3. BotFather пришлёт токен вида `123456789:AA...` — он понадобится ниже

## 2. Проверить локально (необязательно, но полезно)

```bash
cd spbu-schedule-bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

export BOT_TOKEN="твой_токен_от_BotFather"
python bot.py
```

Напиши боту в Telegram `/start` — он ответит и покажет твой `chat_id`.
Затем `/today` и `/tomorrow` должны прислать расписание.
Останови процесс (Ctrl+C) перед деплоем.

## 3. Деплой на бесплатный хостинг (Railway)

Railway — самый простой вариант: не нужен свой сервер, бесплатного тарифа
достаточно для одного лёгкого бота.

1. Зарегистрируйся на [railway.app](https://railway.app) (можно через GitHub)
2. Залей эту папку к себе в GitHub-репозиторий (или используй
   Railway CLI: `railway init` в этой папке — вариант без GitHub)
3. В Railway: **New Project → Deploy from GitHub repo**, выбери репозиторий
4. Railway увидит `Procfile` и `requirements.txt` и сам поставит зависимости
5. Во вкладке **Variables** добавь переменные окружения:
   - `BOT_TOKEN` — токен от BotFather
   - `TIMEZONE` — `Europe/Moscow` (можно не добавлять, это значение и так по умолчанию)
   - `SEND_HOUR` — `20` (время автоматической отправки, по умолчанию)
   - `SEND_MINUTE` — `0`
6. Deploy. В логах должно появиться `Бот запущен...`
7. Напиши боту `/start` в Telegram — он пришлёт твой `chat_id`
8. Добавь в Variables ещё `CHAT_ID` с этим числом и передеплой
   (Railway → Redeploy, или просто сохранение переменной триггерит рестарт)

После этого каждый вечер в 20:00 (можно поменять через `SEND_HOUR`/`SEND_MINUTE`)
бот сам присылает расписание на завтра, плюс `/today` и `/tomorrow` работают
по запросу в любой момент.

Если вместо Railway хочешь Render.com — то же самое, но при создании сервиса
выбери тип **Background Worker**, команда запуска `python bot.py`, и те же
переменные окружения.

## 4. Как поменять сокращения и исключения предметов

Всё в `config.py`, в списке `RULES`. Каждое правило проверяется по порядку,
берётся первое подходящее:

```python
{"match": "Электив. Испанский язык", "exclude": True},          # скрыть предмет
{"match": "...", "subgroup": "2", "exclude": True},              # скрыть только подгруппу 2
{"match": "Французский язык, практическое занятие", "short": "французский"},  # сократить
```

`match` — это начало названия предмета ровно как оно приходит с сайта
(включая «, лекция» / «, практическое занятие» на конце, если оно есть).
Если предмет не подходит ни под одно правило, он попадёт в расписание
как есть, без сокращения — то есть при появлении нового предмета в
следующем семестре ничего не потеряется, просто будет длинное название,
пока не добавишь для него правило.

После изменения `config.py` нужно закоммитить и запушить в GitHub —
Railway передеплоит бота автоматически.

## Если сайт СПбГУ поменяет вёрстку

`scraper.py` ищет конкретные CSS-классы (`studyevent-datetime`,
`studyevent-subject`, `panel-title` и т.д.). Если сайт обновят и бот
перестанет находить пары, скорее всего поменялась разметка — тогда нужно
будет заново посмотреть HTML страницы и поправить селекторы в `scraper.py`.
